# TUI настроек krushitel — своя реализация (v2)

> цель: один экран вместо плоского списка + двух отдельных `stTitleEdit` / `stDummyEdit`.
> всё что ниже — мой вариант, не описание текущего. назад совместимо с `config.toml`, новых ключей нет.

## 0. идея в одном абзаце

настройки = сгруппированный список с несъезжающим курсором + черновик + модальные редакторы.
никаких условных строк что прыгают под ногами (как сейчас с OSD-слотами), никакого мгновенного `saveSettings()` на каждый тоггл.
правишь черновик, видишь грязные строки точкой `•`, выходишь — если грязно, спрашиваем `сохранить? y/n`. `esc` всегда безопасен.

## 1. что не так сейчас (по коду)

смотрел `core/ui/main.go:674-781`, `settings.go:16-51`:

1. плоский `settingsRows()`: включение `titles` вставляет 6 строк посреди списка → `setCur` указывает уже не туда. классика дрифта курсора.
2. половина `Settings` вообще не из TUI правится: `skip_shitty` только в форме эксплоита, `wipe_users`, `brute_passwords`, `tg_bot_token`, `tg_chat_ids` — только руками в `config.toml`.
3. `rowGovCap` крутится по фиксированным ступеням `nextGovCap()` (`main.go:664`) — ввести `750` нельзя.
4. каждый тоггл сразу `saveSettings()`. оступился на пробеле — конфиг уже перезаписан, откатить нечего.
5. два отдельных стейта-редактора (`stTitleEdit`, `stDummyEdit`) с дублированной логикой `enter/esc` + валидацией. новый строковый параметр = новый стейт, так не живём.
6. нет признака "что поменялось", нет поиска, длинные значения обрезаются только в `quoteVal()` без хинта про лимит.

## 2. принципы

- один `stSettings`, один курсор, заголовки секций не выбираются (скипаются при навигации).
- черновик: `draft Settings` + `dirty map[rowID]bool`. `cfg` трогаем только на сохранении.
- строковые/листовые значения — через один generic-модал, не плодим стейты.
- все лимиты из `sanitizeSettings()` (`settings.go:211-250`): 32 / 22 руны, `login 5-32`, `pass 8-32`, только латиница+цифры для dummy (там же где `exploit.ValidateDummy`).
- стиль не меняем: `bannerBlock() + panelS() + centerBlock() + withBottom()`, курсор `▶`, `styleGreen/styleDim/styleBold`, футер снизу.

## 5. навигация и клавиши

| клавиша | действие |
|---|---|
| `↑/↓, tab/shift+tab, j/k` | ход по выбираемым строкам, заголовки секций скипаются |
| `1..9` | прыжок как в меню (опционально, по номерам внутри секции) |
| `enter / space` | bool → тоггл в черновик; значение → открыть модал |
| `←/→, h/l` | для enum/bool быстрое переключение без модала (язык, pps-пресеты) |
| `e` или `enter` на числе | прямой ввод (потолок pps) |
| `esc` | закрыть модал → выйти из настроек; если `dirty` — конфирм `сохранить? (y/n/esc)` |
| `ctrl+s` | сохранить не выходя |
| `ctrl+c` | выход как сейчас, без сохранения черновика |

футер контекстный: на bool — `enter/пробел - переключить`, на строке — `enter - править`, в модале — `enter - ок · esc - отмена`.

## 6. типы строк (вместо `rowSnaps...rowBack`)

```go
type setRowID int
const (
  sSnaps, sXML, sSkipShitty, sWipeUsers,
  sDummy, sBrute,
  sTitles, sChanTitle, sSlot0, sSlot1, sSlot2, sSlot3, sSlot4,
  sGovernor, sGovCap,
  sTgToken, sTgChats, sDiscord,
  sLang, sDebug, sReset, sBack setRowID = iota ... // порядок = порядок на экране
)
type setRow struct {
  id      setRowID
  section string // "" = обычная строка, иначе заголовок (не выбирается)
  label   func(draft Settings) string
  hint    func(draft Settings) string // правая часть / счётчик
  kind    int // kBool, kString, kInt, kList, kAction
}
```

рендер: один `settingsViewV2()` вместо `settingsRows() + settingsView()`.
секции захардкожены порядком выше, никаких `if cfg.Titles { append... }` что двигают индексы — OSD-строки всегда на месте, при `titles=off` рисуются `dim` + `(выкл)` и не открываются (пишем хинт `включи OSDChanger`).

## 7. состояние и сохранение

```go
// в model:
setCur   int
setDraft Settings
setDirty map[setRowID]bool
setOrig  Settings // слепок на входе, для esc-без-сохранения
setModal *setModal // nil = модала нет; иначе один generic-редактор
```

- вход в `stSettings`: `setDraft = cfg; setOrig = cfg; dirty = {}`.
- любой тоггл/правка модала: `setDraft.X = v; dirty[id] = (v != orig.X)`, удаляем из dirty если вернули как было.
- `сохранить`: `sanitizeSettings(&draft); cfg = draft; saveSettings(); scanner.GovernorOn/Cap + fwd.SetDefaultCreds(...) как в loadSettings()` — вынести в `applyLive(draft)`, переиспользовать и там и там.
- `esc` при `len(dirty)>0`: мини-конфирм `есть несохранённое (N). сохранить? y/n`, `y` = сохранить+в меню, `n` = выкинуть черновик.
- `сбросить к дефолту`: конфирм-модал → `draft = defaultSettings()` с сохранением `lang/isActivated/last_*` (чтобы не выкидывало язык и историю), помечаем всё dirty.

никаких новых файлов конфига, формат `config.toml` тот же.

## 8. валидация (таблица = код)

| поле | правило | ошибка |
|---|---|---|
| channel title | `≤32 руны`, `\n/\r` → пробел, пусто = ок | `максимум 32 (у тебя N)` + счётчик `N/32` |
| OSD слот | `≤22 руны`, то же | `максимум 22 (у тебя N)` + `N/22` |
| dummy `login:passwd` | `Cut(":")`, login 5-32, pass 8-32, `[a-zA-Z0-9]`, reuse `exploit.ValidateDummy` | его текст + `нужен формат login:passwd` |
| gov cap | int `≥0`, `0 = авто`, верх клампим `50000` | не число → не закрываем модал, `введи число, 0 = авто` |
| tg token | `trim`, пусто = ок (фича выкл), иначе `≥10` символов | `похоже на обрезок, проверь` (warn, не блок) |
| tg chat id | каждый `trim != ""`, цифры/`-цифры` | `id — число, например 8357976630` |
| brute `a:b` | `trim != ""`, должен содержать `:` | скип пустых молча |
| wipe_users `false→true` | отдельный конфирм | `это сносит лишних юзеров на взломанных. точно? y/n` |

обрезка только через `truncateRunes()` из `settings.go`, никакого реза по байтам (юникод типа `каналютф`).

## 11. краевые случаи

- узкий терминал: строки режутся через уже существующий `fitWidth()/cutStr()`, счётчики `N/32` не дают разъехаться.
- `titles=off` + курсор стоял на слоте → курсор не сбрасываем, строка просто `dim`, `enter` показывает хинт а не модал.
- токен длинный: в списке показываем `•×8 (задан)` а не сам токен, полный виден только в модале.
- `tg_chat_ids` с мусором из toml (`7.5, true` — см. тест) — `applyTomlMap` уже игнорит, модал показывает только выжившие.
- двойной вход в настройки без сохранения — `setOrig` перезатирается на входе, утечки нет.
